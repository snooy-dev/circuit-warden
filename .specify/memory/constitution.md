# Circuit Warden Constitution

## Core Principles

### I. 사용자의 게임 설계 결정권
사용자가 게임 의도·규칙·범위를 결정한다. Codex는 기획 자료의 모순과 미정을 드러내고 확정된 의도 안에서 계획·구현·검증을 수행한다. PPTX와 추론을 승인된 요구사항으로 자동 승격하지 않는다. 게임 구현은 사용자의 명시적 시작 지시 전까지 보류한다.

### II. 별도 docs의 작성·갱신은 필수
docs/에 현재 기획·시스템 설계·기술 구조·아트 기준·진행 상태를 유지한다. specs/<feature>/의 spec, plan, tasks는 진행 중인 변경의 작업 문서이며 docs의 대체물이 아니다. 결정 직후 해당 내용을 수정하고 계획에 문서 영향·갱신 작업을 지정하며 구현 후 동기화한다. 문서 영향이 없으면 이유를 기록한다. docs·코드 불일치가 남으면 완료가 아니다.

### III. 기준 문서와 변경 이력
현재 승인된 규칙의 소유자는 해당 docs 문서 하나다. 개별 변경 명세는 기준 문서와 새 요구사항을 연결한다. 승인 예정 변경과 구현 상태를 구분한다. 문서는 현재 내용으로 갱신하며 현재 선택의 이유만 짧게 유지한다. 결정 연표·변경일지·세션 로그를 누적하지 않는다. 변경 경위는 Git 커밋·diff로 확인한다. 완료한 specs는 docs 반영과 검증 결과의 커밋 보존을 확인하고 참조가 없을 때 후속 정리 변경에서 제거할 수 있다. 미커밋 근거를 삭제하거나 자동 커밋하지 않는다.

### IV. 실행 증거로 검증
비단순 게임 동작 변경에는 요구사항과 대응하는 자동 테스트를 계획·실행한다. 순수 Python 규칙 테스트, 실제 Pico2D 창·입력·화면 검사, 사람의 플레이 판단을 구분한다. 변경별 verification.md에 실제 명령·결과·미실행 이유·문서 갱신을 기록한다. 체크박스나 의미 검토만으로 실행 성공을 주장하지 않는다. 문서만 수정하면 문서 검증을 적용하고 불필요한 게임 테스트를 만들지 않는다.

### V. 단일 워크플로우와 기술 제약
진행 체계는 Spec Kit, AI 에이전트는 Codex, 게임은 Python + Pico2D다. Agent Sprite Forge와 pixelfx는 에셋 작업에서 사용하는 도구다. 게임 환경과 도구 환경은 분리한다. 외부 서비스 사용 가능 여부와 개별 생성 작업 승인은 구분한다. 웹/API 서버·DB·다른 엔진을 기본값으로 도입하지 않는다.

## Development Workflow

1. 원본 자료·현재 docs·결정·미정을 읽고 기획 대화를 기록한다.
2. specify와 필요한 clarify로 요구사항·설계 승인·docs 영향을 기록한다.
3. plan과 tasks로 기술 선택·작업·테스트·docs 갱신을 연결한다.
4. analyze로 모순·누락을 점검하고 중요한 미정을 해결한다.
5. 구현 시작 지시가 있는 범위만 implement로 수행한다.
6. docs·결정·진행 상태·검증 증거를 갱신한다.
7. converge가 발견한 작업을 같은 흐름에서 보완한다. docs 미갱신도 남은 작업이다.

## Governance

이 문서는 도구의 일반 예시보다 우선하는 프로젝트 운영 기준이다. 사용자의 새로운 명시적 지시가 우선한다. 현재 규칙을 직접 갱신하고 변경 경위는 커밋 시 메시지와 diff에 보존한다. 승인 범위 안의 반복 작업마다 확인을 요구하지 않는다. 게임 설계를 대신 결정하지 않는다. 스킬·도구는 로컬 설치로 유지하고 정책·템플릿·문서는 Git에 남긴다.
