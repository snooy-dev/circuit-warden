## Intent & Scope

예약 공격의 첫 자세·효과 동기화, 표시 전환 직전 클릭, 전하 효과 성능, 예외 시 참조 해제, 행동 판정 중복을 수정한다. 게임 규칙·자산 모양·전류 시간·배치·입력 키는 유지한다. 기존 사용자 점프 PNG 8개와 tmp는 보존하고 커밋에서 제외한다. 새 아트·적·피해·물리·PR·push는 범위 밖이다.

## User Scenarios & Testing (mandatory)

### User Story 1 - 늦은 프레임에도 입력과 효과 일치 (Priority: P1)

**Why this priority**: 실제 조작이 잘못되거나 공격 첫 자세가 생략되는 문제다.
**Independent Test**: 대시 종료와 예약 만료 경계의 80ms 갱신, F6와 클릭의 같은/다음 이벤트 묶음을 재현한다.

**Acceptance Scenarios**:
1. **Given** 대시 잠금 종료 직전 공격 예약, **When** 긴 갱신에서 예약 공격 시작, **Then** 캐릭터와 새 베기는 모두 첫 프레임에서 표시된다.
2. **Given** 이전 화면에서 누른 전하 클릭이 대기 중, **When** F6 표시 변경, **Then** 그 클릭을 새 화면 좌표로 잘못 해석해 공격하지 않는다.

### User Story 2 - 모양을 보존하는 빠른 전하 효과 (Priority: P1)

**Why this priority**: 현재 전하 5개에서도 프레임 예산을 초과한다.
**Independent Test**: 변경 전후 같은 입력의 RGBA 출력과 같은 장면의 연속 순간이동 비용을 비교한다.

**Acceptance Scenarios**:
1. **Given** 같은 시각·전환 값·끝점·seed, **When** 변경 전후 출력 비교, **Then** 모든 표적 샘플의 RGBA 바이트가 같다.
2. **Given** 전하 5개의 동일 연속 이동, **When** 같은 장비에서 교대 측정, **Then** 픽셀 계산 95백분위가 유의하게 줄고 16.67ms 이하를 목표로 한다.

### User Story 3 - 실패 정리와 행동 규칙 단일화 (Priority: P2)

**Why this priority**: 오류 보관 때 메모리가 남고 허용 규칙이 중복돼 유지보수 위험이 있다.
**Independent Test**: 갱신 예외를 보관한 채 장면을 닫고 약한 참조를 확인하며 입력·착지·대시 회귀를 실행한다.

**Acceptance Scenarios**:
1. **Given** 첫 객체/노드의 갱신 실패, **When** 예외를 보관한 채 종료, **Then** 무관한 객체/노드는 해제된다.
2. **Given** 마지막 행동 예약, **When** 허용 시점 도달, **Then** 기존 규칙대로 한 번 실행하며 세 요청 플래그를 중복 보관하지 않는다.

### Edge Cases

같은/분리된 입력 묶음, 무효 출력·포커스 상실·종료, 예약 만료 경계, 착지 연속 점프, 공중 대시 제한, 가로/세로/대각·짧은/분수 끝점, 양방향 전환과 안정 상태, 예외 보관 중 닫기를 포함한다.

## Requirements (mandatory)

### Functional Requirements

- **FR-001**: 예약 공격 시작 갱신에서도 캐릭터·베기 첫 프레임을 함께 표시한다.
- **FR-002**: 요청한 표시 전환 전에 쌓인 클릭을 이전 화면 기준으로 처리하고 종료·무효 출력 안전성을 유지한다.
- **FR-003**: 전하 합성·연결 효과의 RGBA 모양·샘플 선택·시간을 보존하면서 CPU 비용을 줄인다.
- **FR-004**: 월드·UI 갱신 실패 후 보관된 예외가 순회 목록을 통해 무관한 객체를 붙잡지 않는다.
- **FR-005**: 예약 행동 허용 판정을 한 곳으로 모으고 세 요청 플래그를 제거한다.
- **FR-006**: 사용자 변경과 원본 자산을 보존하고 검증한 수정·문서·근거만 로컬 커밋한다.

### Constraints

- Python + Pico2D와 기존 패키지 경계를 유지한다. 게임과 도구 환경을 분리한다.
- 효과 프레임·색·알파·재생 시간을 줄여 성능을 높이지 않는다.
- 변경된 경계는 회귀 검사, 화면·입력은 실제 SDL 검사, 성능은 동일 조건 비교로 확인한다.

## Success Criteria (mandatory)

- **SC-001**: 감사의 재현 사례가 수정 후 통과하고 관련 회귀가 유지된다.
- **SC-002**: 전하 합성·전류의 광범위한 결정적 샘플에서 변경 전후 바이트 차이가 0이다.
- **SC-003**: 같은 연속 이동 검사에서 픽셀 계산 95백분위가 기준보다 30% 이상 감소한다. 16.67ms 초과 여부도 공개하며 장비 전체 FPS 보장으로 확대하지 않는다.
- **SC-DOC**: docs·spec/plan/tasks·실제 검증·커밋 범위가 일치한다.

## Assumptions & Open Decisions

60 FPS는 기존 목표이며 모든 장치 보장은 아니다. 성능 수용 기준은 이번 기술 검증 기준이다. 네이티브 배열 연산과 순수 Python 개선은 출력 동일성·측정 결과로 선택하며 새 게임 규칙은 추가하지 않는다.
