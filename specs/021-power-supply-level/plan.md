# Implementation Plan: 첫 레벨 전원 구역

## Summary

구조물 충돌을 먼저 배치하고, ImageGen 원화를 hi-bit 원경과 조립식 구조·부품으로 가공한다. 이동 순서를 먼저 정하고 구역 실루엣을 나눈 뒤 원경과 전경을 쌓는 데 Team Cherry의 제작 기록을 참고했다. [Team Cherry 제작 기록](https://www.teamcherry.com.au/blog/hollow-knight-then-and-now) · [개발진 인터뷰](https://www.pcgamer.com/how-to-design-a-great-metroidvania-map/)

## Technical Context

1280×720 기준, 월드 3840×720, 픽셀 1:1 기준, 수평 추적 카메라와 y 고정. 배치의 좌상단 기준 좌표를 Pico2D의 중앙 원점·위쪽 y로 변환한다. 바닥 y=540, 워든 높이 83·달리기 240/s·완전 점프 166. 도약 구간의 상승량과 수평 공백을 해당 범위 안으로 배치한다. 방열판 앞뒤의 중간 발판은 돌아올 때도 사용한다.

## Constitution Check

기존 레벨·충돌·카메라·스프라이트를 사용하고 첫 레벨 진입점을 바꾼다. 기존 훈련장은 명령행에서 유지한다. 진행 문서에는 사용자 요청과 작업 기본값을 구분한다.

## Project Structure

배치와 가공된 텍스처는 `assets/levels/power-supply/`, 로컬 원화와 프롬프트·검토 자료는 `art/levels/power-supply/`, 런타임은 `game/power_supply_map.py` 및 기존 장면에 둔다. 원경 → 뒷장식 → 구조물 → 워든·적·전하 → 전경으로 그린다. 원경은 720×360 논리 픽셀을 3배로 펼치고 카메라 x 이동의 35%를 적용한다. 소품은 공통 24색을 기준으로 축소하고 배치에 맞춰 음영을 설정한다. 보행면에 구조의 상단 픽셀을 정렬한다.

## Validation

번들·웹 경로·Tiled 내보내기와 SDL 런타임 검사를 수행한다. 브라우저 미리보기는 그리기 순서를 유지해 도형 레이어를 한 층으로 합친 사본을 사용한다. 브라우저의 평면 보행과 Pico2D의 점프 검증을 구분한다.

## 먼지와 팬 연출

원화 편집으로 원경의 팬 날개를 비우고 표면별 먼지를 추가한다. 투명 먼지 시트를 hi-bit로 가공하고 바닥·발판 끝에 장식 오브젝트로 배치한다. 팬 회전자는 빈 하우징의 픽셀 좌표에 중심과 반지름을 맞추고 원경과 같은 패럴랙스 좌표에서 그린다. 실제 SDL에서 서로 다른 시점의 팬 영역과 고정 프레임을 대조하고 흡기구·전력 변환부·출력 단자 화면의 가독성을 확인한다.

## 공통 픽셀 격자

첫 레벨의 배경·지형·캐릭터·효과를 세로 360픽셀의 SDL 텍스처에 함께 그린 뒤 최근접 확대한다. 너비는 창 화면비에 맞추며 텍스처는 같은 크기에서 재사용한다. 게임 좌표와 창 입력은 기존 출력 크기를 기준으로 계산한다. 화면 크기 전환과 실제 전하 클릭을 SDL로 검사한다.

## 상단 케이블의 낙뢰로 시작

기존 상단 케이블에서 아래쪽 워든으로 이어지도록 전류 시작 좌표를 지정하고 입구 장식 인렛을 맵에서 제거한다. 기존 전류 애니메이션과 340ms 등장, 즉시 입력 처리, 스폰과 충돌 배치를 재사용한다. 실제 SDL에서 케이블과 방전의 연결, 워든 등장, R 재시작과 조기 이동을 확인한다.

등장 전용 pixelfx 시트에 선행 방전, 굵은 번개와 국부 섬광, 바닥 불꽃을 굽는다. 낙뢰 타격 시점에 워든이 떠오르기 시작한다. 기존 340ms 등장과 입력 조기 종료를 유지하며 일반 전하 연결에는 기존 에셋을 사용한다. 실제 SDL에서 첫 타격·잔광과 재시작·입력 중단을 확인한다.

시작 케이블의 굽은 부분에만 찢어진 피복과 노출 심선을 합성한다. 심선 끝에 시작 좌표를 지정하고 기존 타격 시트를 다시 굽는다. 맵 배치와 실제 SDL에서 방전과 심선의 접점을 확인한다.

타격 시각부터 100ms 동안 첫 레벨의 렌더 카메라를 논리 픽셀 단위로 흔든다. 등장 클립의 시간으로 흔들림을 계산하고 그리기가 끝나면 기존 카메라 중심을 복원한다. SDL에서 타격 동기화, 픽셀 단위 변위, 원위치, R 재시작과 조기 입력을 확인한다.

## 레벨 동선 재설계

Team Cherry가 첫 구간을 조작 학습에 사용하고 교차로의 연결된 길에서 탐색과 복귀를 유도한 방식을 참고한다. 흡기구에서 단독 발판으로 안전하게 연습하고, 첫 방열판에서 같은 점프를 연속으로 사용한다. 변환부는 발판 위와 적이 있는 바닥으로 갈라졌다가 합류하고, 두 번째 방열판을 지나면 출력 단자 앞 평지가 열린다. [초반 플레이](https://www.teamcherry.com.au/blog/kings-pass-gameplay-playtests-conventions-team-cherrys-working-hard) · [교차로 설계](https://www.teamcherry.com.au/blog/the-forgotten-crossroads-a-hollow-knight-tour)

워든 몸통 48×83, 완전 점프 높이 166, 달리기 240/s를 기준으로 블록아웃을 잡는다. 1단 발판 윗면은 바닥 위 134, 밑면은 110으로 둔다. 중앙 상부로 오르는 단차는 120, 양쪽 상부 사이 간격은 80이다. 방열판은 지면에서 192 높이이며, 앞뒤 발판에서 58 높이로 오를 수 있다. 훈련장 발판의 바닥 여유는 최소 104로 맞춘다.

기존 금속 발판·방열판의 그림, 충돌, 먼지, 전하를 함께 옮긴다. 게임 설계 문서에는 동선, 기본 게임플레이 문서에는 훈련장 배치를 갱신한다. 실제 SDL 입력으로 하부 주행, 틈 하강, 양방향 점프, 상부와 하부의 합류 및 출력 도달을 확인한다.

## 전망대와 전력 변환부 재제작

게임은 1280×720 시야를 640×360 픽셀 격자로 표시한다. 세계 좌상단을 원점으로 하는 높이 720, 바닥 y=540의 맵을 사용한다. 48×83 몸통, 최대 점프 높이 166, 달리기 240/s, 전하 거리 300으로 흡기구 연습 → 정비 전망대 → 하부 교전로 또는 상부 전하로 → 출력부를 배치한다. 바닥 위 100 이상 통과 여유와 중앙의 낙하 착지 발판을 둔다.

할로우 나이트의 초반 조작 연습과 연결된 경로를 참고해 점프 발판 다음에 전망대를 둔다. 레인 월드의 환경 관찰을 참고해 전하와 적, 접점의 활동 상태가 다음 움직임을 고르는 단서가 되게 한다. [왕의 길](https://www.teamcherry.com.au/blog/kings-pass-gameplay-playtests-conventions-team-cherrys-working-hard) · [잊혀진 교차로](https://www.teamcherry.com.au/blog/the-forgotten-crossroads-a-hollow-knight-tour) · [Videocult 개발자 설명](https://blog.playstation.com/?p=187776).

기존 `PowerSupplyMap`의 맵 계약을 사용한다. 새 원경과 정비용 철재를 생성해 블록아웃에서 검증한 충돌 사각형과 일치시킨다. 회전 팬과 등장 컷신의 접점은 유지한다. 상부 방전은 3.2초 주기에서 0.6초 예고한 뒤 0.5초 동안 접점 사이에 피해를 준다. 상부 착지 실패가 하부 진행으로 이어지도록 배치한다. 해당 시간은 조작 시험값이다. 신규 전역 능력이나 후속 구역을 추가하지 않는다.

기본 실행과 직접 SDL 경로 입력, 맵·전하 좌표 검사, 전망대·합류·출력 화면을 확인한다. 완료 후 게임 설계·아트 기준·진행 상태·검증 기록을 갱신한다.

## 정비 샤프트와 순환 동선

출시판 잊혀진 교차로 지도에서 흙의 마을 아래 진입, 높이가 다른 가로 통로를 잇는 수직 통로와 서로 다른 높이의 두 수정 봉우리 출구를 확인했다. 출시판 Outskirts 방 데이터에서는 시작부 `SU_A22`가 `SU_A23`·`SU_A43` 및 단일 출입구의 대피처 `SU_S01`에 연결된다. 서쪽의 긴 `SU_C02`는 `SU_A07`과 `SU_A45`를 잇는다. 전원 구역에서는 이 관계를 기능별 방, 양쪽 샤프트, 원래 높이로 돌아오는 동선으로 적용한다. [출시판 교차로 지도](https://www.pdf-archive.com/2017/03/01/hollow-knight-all-maps/hollow-knight-all-maps.pdf) · [게임 지형과 방 연결 추출본](https://henpemaz.github.io/Rain-World-Interactive-Map/map.html?difficulty=1&region=SU) · [추출 절차](https://github.com/henpemaz/Rain-World-Interactive-Map#readme).

아래층은 흡기구 → 정비실 → 변환실 → 배기 샤프트다. 위층은 출력실 ← 중앙 샤프트 ← 배선실 ← 배기 샤프트다. 중앙 샤프트가 정비실과 만나 고리를 완성한다. 층간 이동은 같은 월드 좌표와 기존 충돌·물리로 처리한다. 바닥과 등장 접점은 월드 좌표를 유지하고 위쪽으로 맵을 늘린다. 실제 카메라의 수직 추적과 화면 경계를 검사한다.

기존 아트의 판금·팬·구리 코일·출력 단자를 재배치하고, 필요한 벽체와 천장에 기존 이미지를 절단해 사용한다. 방전의 예고와 피격은 배선실에 필요하다. 새 조작, 저장, 능력, 문 잠금은 범위 밖이다. 게임 설계, 아트 기준, 아키텍처 및 진행 상태를 실제 구현에 맞춘다.

## 배전망 복구와 상층 귀환

Team Cherry가 공개한 왕의 길 화면은 어두운 고형 지형으로 길을 좁히고, 교차로 입구는 우물과 바닥을 중심 조명으로 묶는다. Goam 방의 발판과 움직이는 위험은 조용한 원경 앞에 놓인다. Videocult의 수직 방 화면도 통과하는 공간을 밝게 남기고 외곽을 큰 어둠으로 묶는다. 이 구도는 장식의 밀도와 플레이 표면을 정하는 기준이다. [왕의 길](https://www.teamcherry.com.au/blog/kings-pass-gameplay-playtests-conventions-team-cherrys-working-hard) · [교차로·Goam 방](https://www.teamcherry.com.au/blog/hollow-knight-then-and-now) · [레인 월드 실제 수직 방](https://commons.wikimedia.org/wiki/File:Rain_World_screenshot_-_2016-05-31_16_15_34_climbing.png).

4320×1920 월드의 하층 변환실과 배전실, 중층 전력교와 차단실, 상층 귀환로를 연속 좌표로 배치한다. 두 장치는 접지 상태에서 가까이 서서 W로 작동시킨다. 장치의 상태가 동적 충돌·출력·표시에 함께 반영된다. 출력 셔터와 귀환 셔터는 전하로 건너뛸 수 없다. 실제 SDL에서 시작 → 닫힌 출력 → 릴레이 → 교량 → 차단기 → 귀환 → 출력 → R을 검사한다.

기존 원경의 팬 부분과 소수의 소품만 사용하고, 방별 명암과 구조 면은 플레이 지형의 윤곽에 맞춰 배치한다. 게임 설계·아트 기준·조작·기술 구조·검증 기록을 갱신한다.
