# Feature Specification: 스프라이트 표시·재생과 이미지 수명

**Created**: 2026-11-11
**Status**: Ready
**Input**: 상용 엔진 조사에 따른 스프라이트 기능의 명세·계획 작성. 실 스프라이트 시트는 반영하지 않고 로컬 임시 출력 검사에만 사용한다. 임시 검사는 사용자 직접 확인 전 제거하지 않는다. 구현에는 Ponytail을 적용한다.
**Design approval**: 2026-11-11 사용자가 “이 계획을 구현한다”고 지시했다. 게임 정책·실 시트 영구 채택 승인과는 구분한다.
**Implementation authorization**: 2026-11-11 사용자가 이 계획의 구현과 중간 커밋을 지시했다. 임시 출력 검사는 미추적이며 사용자 직접 확인 전 제거하지 않는다.

## Intent & Scope

개발자가 한 이미지의 일부를 정지 그림 또는 시간 기반 애니메이션으로 월드와 UI에 표시할 수 있게 한다. 여러 개체는 원본 이미지를 공유하면서 독립적으로 재생한다. 현재 객체·레벨·Canvas·렌더러의 수명과 표시 순서를 유지한다.

포함: 이미지 로딩·중복 방지·종료 정리, 프레임 영역·기준점, 프레임별 시간, 반복/단발 재생, 동작 전환, 위치·크기·수평 반전·투명도, 로컬 임시 출력 확인 절차.
제외: 실 스프라이트의 게임 등록·배포·커밋, 아트 생성/보정, 편집기, 자동 패킹·트리밍, 범용 메타데이터 임포터, 사운드/폰트 로더, 비동기 로딩, 장면 간 캐시, 회전, 애니메이션 이벤트·상태 머신, 전투/충돌/이동 정책, 장치 리셋 자동 복구.

## User Scenarios & Testing (mandatory)

### User Story 1 - 시트 일부를 올바르게 표시한다 (Priority: P1)

**Why this priority**: 정지 프레임과 자원 수명이 모든 재생의 기반이다.
**Independent Test**: 영역과 모서리를 식별할 수 있는 임시 시트에서 특정 프레임을 월드·UI에 표시한다.

**Acceptance Scenarios**:
1. **Given** 여러 프레임이 있는 이미지, **When** 하나를 지정, **Then** 그 영역만 지정 위치·크기·기준점으로 표시된다.
2. **Given** 같은 이미지를 쓰는 두 개체, **When** 한쪽의 수평 반전과 투명도를 변경, **Then** 다른 개체의 표시 상태는 바뀌지 않는다.
3. **Given** 화면 크기·카메라·UI 배율이 변경됨, **When** 다시 표시, **Then** 기존 월드/UI 좌표 변환과 표시 순서를 유지한다.

### User Story 2 - 동작을 시간에 맞게 독립 재생한다 (Priority: P2)

**Why this priority**: 게임 프레임 수와 무관하게 원본 동작의 시간을 유지한다.
**Independent Test**: 서로 다른 지속 시간을 가진 프레임들을 동일 총 경과 시간으로 갱신해 비교한다.

**Acceptance Scenarios**:
1. **Given** 프레임별 시간이 다른 반복 동작, **When** 여러 프레임을 넘는 시간이 경과, **Then** 경과 시간에 대응하는 프레임으로 진행한다.
2. **Given** 단발 동작, **When** 전체 시간이 경과, **Then** 마지막 프레임과 완료 상태를 유지한다.
3. **Given** 재생 중인 동작, **When** 같은 동작을 재지정, **Then** 기본적으로 이어 재생하고 명시적 재시작만 처음으로 돌아간다. 다른 동작은 첫 프레임에서 시작한다.
4. **Given** 같은 클립을 공유하는 두 개체, **When** 한 개체만 갱신, **Then** 다른 개체의 재생 시점은 유지된다.

### User Story 3 - 로딩과 종료에 일관된 결과를 얻는다 (Priority: P1)

**Why this priority**: 중복 로딩과 해제 오류는 실행 안정성에 직접 영향을 준다.
**Independent Test**: 로더 대역과 정리 기록으로 중복 요청·부분 실패·종료 순서를 검사한다.

**Acceptance Scenarios**:
1. **Given** 동일 장면에서 같은 실제 경로의 이미지 요청, **When** 여러 개체가 요청, **Then** 성공한 로딩은 한 번만 수행하고 공유한다.
2. **Given** 파일 누락·읽기 실패·잘못된 프레임 정보, **When** 준비, **Then** 해당 파일/필드를 식별할 수 있는 오류를 내며 실패 항목을 정상 자원으로 저장하지 않는다.
3. **Given** 장면 진입 또는 객체/UI 정리 중 실패, **When** 종료 처리, **Then** 남은 자원 정리를 시도하고 원인 오류를 보존한다.
4. **Given** 종료된 장면의 이미지 참조가 외부에 남음, **When** 다시 표시 시도, **Then** 해제된 자원을 사용하지 않고 명시적으로 실패한다.

### User Story 4 - 사용자가 임시 출력 결과를 확인한다 (Priority: P3)

**Why this priority**: 사용자 직접 확인은 자동 검사로 대체할 수 없다.
**Independent Test**: 재실행 가능한 로컬 임시 화면과 실행 방법을 제공하고 사용자 확인을 기다린다.

**Acceptance Scenarios**:
1. **Given** 임시 확인용 실 시트, **When** 출력 검사 준비, **Then** 게임용 자산·기본 실행 화면·커밋에 포함하지 않는다.
2. **Given** 자동 검사와 Codex 화면 관찰 완료, **When** 사용자가 아직 확인하지 않음, **Then** 임시 실행 파일·설정·필요한 임시 복사본을 유지하고 확인 대기로 보고한다. 창이 닫혔다고 확인 완료로 간주하지 않는다.
3. **Given** 사용자가 출력이 정상이라고 직접 확인, **When** 임시 검사 정리, **Then** 이번 작업에서 만든 임시 자료만 제거하고 실 시트 원본·구현·자동 회귀 검사를 보존한다.
4. **Given** 사용자가 출력 문제를 지적, **When** 보정과 재검사, **Then** 수정 결과를 다시 확인할 때까지 임시 자료를 유지한다.

### Edge Cases

빈 클립, 0/음수/비유한 지속 시간과 dt, 이미지 밖 영역, 비정수/0 크기 영역, 프레임 하나, 정확한 프레임/클립 종료 경계, 여러 주기를 넘는 dt, 기준점이 다른 프레임, 반전 시 기준점, 유효하지 않은 출력 크기, 같은 경로의 별칭, 한 이미지 로딩 후 다음 로딩 실패, 외부 참조/예외 traceback이 남은 종료, 반복 정리, 기존 이미지 없는 장면 호출.

## Requirements (mandatory)

### Functional Requirements

- **FR-001**: 이미지 일부 또는 전체를 프레임으로 지정해 정지 표시한다. 영역과 기준점을 검증한다.
- **FR-002**: 월드·UI에서 위치·크기·수평 반전·투명도를 적용하고 기존 정렬·숨김·유효 출력 처리를 유지한다. 공유 이미지의 표시 상태는 다른 호출에 남기지 않는다.
- **FR-003**: 프레임마다 양수 지속 시간을 지정하며 개체별 재생 상태를 분리한다. 표시 호출 자체는 시간을 진행시키지 않는다.
- **FR-004**: 반복/단발, 현재 프레임/완료 상태, 같은 동작 유지/명시 재시작/다른 동작 전환을 지원한다.
- **FR-005**: 장면 안에서 동일 실제 경로를 한 번 로딩한다. 실행 작업 폴더가 달라도 같은 지정 기준 경로를 사용한다. 이미지 준비는 표시·갱신 루프 밖에서 한다.
- **FR-006**: 로딩·데이터 오류를 식별 가능하게 보고하고 실패를 정상 캐시에 남기지 않는다.
- **FR-007**: 장면 종료·전환·부분 초기화 실패에서 객체와 UI 정리를 먼저 시도하고 이미지 자원을 출력 장치보다 먼저 정리한다. 반복 정리는 무해하고 닫힌 참조는 사용을 거부한다.
- **FR-008**: 실 스프라이트 시트와 그 임시 설정·실행 연결은 게임 자산·기본 실행 경로·버전 관리에 반영하지 않는다.
- **FR-009**: 임시 화면 검사는 사용자 직접 확인 전 제거하지 않는다. 확인 후 이번 임시 자료만 정리하고 원본과 자동 회귀 검사를 보존한다.
- **FR-010**: 기존 객체·UI·장면의 호출 방식과 수명 동작을 보존한다. 새 기능 없이 실행하는 기존 경로도 동작한다.
- **FR-DOC**: 자동 결과, Codex 관찰, 사용자 확인, 임시 자료 정리 상태를 별도로 기록한다.

### Constraints

- Python + Pico2D를 유지하고 클리핑 드로우를 우선 사용한다. 구체 API와 제한은 plan에서 다룬다.
- 구현에는 Ponytail full을 적용한다. 기존 구조·표준 라이브러리를 우선하며 추가 패키지를 요구하지 않는다.
- 명세·계획 작성 단계에서 실 시트 복사·새 아트 제작·게임 실행을 하지 않는다.
- 임시 검사 삭제에 관한 사용자 대기는 필수다. 일반 단계마다 추가 승인 대기를 만드는 규칙은 아니다.

## Success Criteria (mandatory)

- **SC-001**: 지정 영역의 모서리·방향·기준점·크기가 월드/UI와 두 가지 출력 크기에서 기대와 일치한다.
- **SC-002**: 동일 누적 시간에 대한 프레임 선택이 갱신 분할 방식과 무관하게 일치하고, 경계·반복·단발·독립 재생 자동 검사를 통과한다.
- **SC-003**: 같은 이미지 두 번 요청에서 로딩 한 번, 종료에서 유효 텍스처 해제 한 번, 외부 잔존 참조의 사용 거부가 확인된다.
- **SC-004**: 실 시트/임시 실행 자료의 추적 파일이 없고, 사용자 확인 전 보존 및 확인 후 제한된 정리가 확인된다.
- **SC-DOC**: docs·명세·계획·후속 tasks·검증 상태가 일치하며 실행하지 않은 항목을 성공으로 표시하지 않는다.

## Assumptions & Open Decisions

- feature/engine의 a32333c를 기준으로 feature/sprite-runtime에서 작업한다. main의 무관한 수정은 포함하지 않는다.
- 실 시트의 영구 채택·위치·게임 규격은 미정이며 이번 계획의 필수 결정이 아니다. 임시 검사 직전에 실제 사용할 로컬 원본과 시트 배치·기준점·시간 정보를 확인한다.
- 삭제 대상인 “테스트”는 실 시트를 사용하는 임시 화면 검사 실행 파일·임시 설정·복사본이다. 자동 회귀 검사의 삭제 요청으로 확대하지 않는다.
- 로컬 검사에 원본을 읽기 전용으로 참조하면 복사본도 필요 없다. 원본을 수정·이동·삭제하지 않는다.
- 클리핑 함수가 내부 그리기 실패 코드를 반환하지 않는 Pico2D 한계는 기술 계획과 실제 화면 검사 항목에 명시한다.

## Engine Integration Scope

2026-11-11 사용자가 게임 구현 전에 미구현 기반을 먼저 보완하고 `feature/engine → main` PR을 생성하도록 지시했다. `feature/sprite-runtime`의 기존 구현을 `feature/engine`의 패키지 구조에 통합한다. 게임 브랜치 이름은 사용자가 `feature/character-movement`로 선택했다.

- **FR-011**: 게임용 스프라이트 API는 `game_framework/sprites.py`, 영역 검증은 `game_framework/drawing.py`, 출력 실행은 `engine/rendering/drawing.py`, 장면 이미지 정리는 `game_framework/level_scene.py`에 배치한다. engine은 game_framework에 의존하지 않는다. 기존 `from sprites import ...`와 전체 이미지 그리기는 호환을 유지한다.
- **SC-005**: 현재 패키지 구조의 기존 검사와 스프라이트 회귀 검사를 함께 통과하고, 실제 PNG·SDL 출력 및 자원 정리를 검사한다.
- idle v7·Run v4의 영구 복사와 이름 변경, `.gitattributes`, 캐릭터 조작은 PR 생성 후 별도 게임 브랜치 범위다. FR-008의 미반영 조건은 이 엔진 변경에 적용하며 후속 게임 작업의 최신 사용자 허가를 제한하지 않는다.
- 이전 임시 화면의 사용자 직접 확인·정리는 미확인 상태로 유지한다. 최신 구현 지시를 과거 화면 확인 완료로 기록하지 않는다.
