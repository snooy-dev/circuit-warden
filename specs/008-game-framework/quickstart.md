# 게임프레임워크 검사 계획

모든 계획의 구현이 승인됐으며 아래 실행 절차는 각 계획 구현 후 검증한다. [분리 계획](plan.md)에 따라 P1은 창 없는 검사, P2는 기존 main.py 도형 검사, P3은 월드 데모, P4는 독립 UI 검사, P5는 아래 통합 검사를 수행한다. 아래 framework_demo.py는 아직 없으며 해당 계획 승인 후 구현·검증할 실행 절차다. 통합 실행을 P1의 완료 조건으로 요구하지 않는다.

작업 폴더의 PowerShell에서 실행한다. 기존 저장소의 게임 환경을 재사용한다.

```powershell
& D:/GitHub/circuit-warden/.venv/Scripts/python.exe -m unittest discover -s tests -v
& D:/GitHub/circuit-warden/.venv/Scripts/python.exe framework_demo.py
```

도형이 시간에 따라 이동한다. 왼쪽 클릭은 클릭 위치에 객체 생성, 오른쪽 클릭은 가장 최근 객체 제거, Space 또는 마우스 가운데 버튼은 검사 레벨 왕복, Escape 또는 창 닫기는 종료다. 전환 후 이전 도형이 사라지고 새 레벨 초기 배치 도형만 남아야 한다. 기존 main.py 검사도 유지한다. 실제 게임 규칙이나 아트는 아니다.

자동 검사는 서로 다른 레벨의 규칙 격리, 입력 후 업데이트·업데이트 후 렌더링, 이동의 단일 적용, 렌더링 전후 상태 불변도 확인할 예정이다.

겹치는 도형으로 서로 다른 뎁스·동률 안정성·한 객체의 여러 이미지 사이에 다른 객체 이미지 끼우기·실시간 뎁스 변경을 확인한다. 월드의 뎁스 값을 크게 바꿔도 화면 UI가 위에 남아야 한다. 자동 검사는 렌더 정렬 전후 객체 업데이트 순서가 같은지도 확인할 예정이다.

Canvas 검사는 두 겹친 패널과 각 자식 도형으로 한다. 뒤 패널 자식의 형제 뎁스를 크게 해도 앞 패널보다 뒤에 있어야 한다. 부모 이동은 자식 위치에 합산되고, 숨김은 하위 트리만 그리지 않으며, 제거는 하위 트리 전체를 다음 호출/렌더에서 제외해야 한다. UI 정렬은 update 등록순을 바꾸지 않아야 한다. 이 검사는 계획이며 아직 실행하지 않았다.

추가 렌더 검사는 화면 밖에서 이동 중인 도형이 경계에 들어오는 경우, 중심은 밖이지만 일부가 보이는 큰 도형, 보기 원점 이동에도 고정된 UI, 부모 그림은 밖이지만 자식은 안인 UI로 한다. 서로 겹친 반투명 도형과 불투명 도형의 앞뒤를 바꾸고 반투명 UI 아래 월드가 비치는지 확인한다. 공유 이미지의 다른 opacity와 그리기 실패 뒤 상태 복원은 자동 검사에 포함한다. 모두 미실행 계획이다.

가변 출력 검사는 같은 화면비의 다른 크기, 다른 화면비, 가능한 DPI 환경, 창/보더리스 전체화면 전환·복귀·최소화로 수행한다. 월드 좌표 불변·UI 루트 기준점/그림 크기·마우스 위치 일치·화면 밖 판정과 복귀 후 자원 표시를 확인한다. P2 도형 검사는 아래 F6/F11 조작과 실제 SDL 자동 검사로 확인했다. 월드/UI 결과는 각 선행 구현 후 검증한다.

## P2 독립 검사

`& D:/GitHub/circuit-warden/.venv/Scripts/python.exe main.py`를 실행한다. F6는 두 검사 창 크기를 왕복하고 F11은 보더리스 전체화면/창 모드 복귀다. 창 테두리 드래그와 최소화/복구 뒤 마우스 표시와 도형을 확인한다. Space/마우스/Escape 계약은 유지한다. 실제/모의 DPI 증거는 verification에서 구분한다.

실제 창을 자동 검사하고 출력 PNG를 저장하려면 기존 폴더를 인자로 준다. 약 5초 뒤 자동 종료한다.

```powershell
& D:/GitHub/circuit-warden/.venv/Scripts/python.exe tests/display_smoke.py <기존-출력-폴더>
```

이 검사는 실제 SDL 크기/모드/최소화/복구와 마우스 이벤트를 검사하며 물리 키보드 입력이나 다른 DPI 모니터 이동을 대신하지 않는다.
