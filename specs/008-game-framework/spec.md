# Feature Specification: 레벨·씬·게임모드 기반 게임프레임워크

**현재 실행 근거**: 2026-11-10 사용자가 각 계획을 새 채팅에서 구현하고 독립 계획을 별도 워크트리에서 병렬 진행하도록 지시했다. 이전 검토 대기는 해제됐다. P1/P2부터 착수하고 P3는 P1/P2, P4는 P3, P5는 P1~P4의 검증된 커밋에 의존한다. 상세 기술 선택은 제안 기본값으로 구현하며 별도 사용자 확정으로 과장하지 않는다.

**Created**: 2026-11-10
**Status**: 구현 승인 — 계획별 의존 순서 준수
**Input**: 게임프레임워크 개발 요청. 레벨은 배치를 보관하고 씬은 렌더링 구조, 게임모드는 레벨별 규칙 객체라는 사용자 의도 제안. 현재 물리·별도 시뮬레이션 없음. 이미지별 뎁스와 월드/UI 구분을 요청했다.
**Design approval**: 최종 승인 없음. 역할 의도와 기술 가정을 구분한다. Renderer는 사용자 지정 이름이다. Level·Canvas·Renderer의 구체 자료 구조와 Canvas 최소 계층은 Codex의 미승인 제안이며 architecture에서 검토한다.
**Implementation authorization**: 사용자가 모든 계획을 새 채팅에서 구현하도록 지시했다. P1/P2는 별도 워크트리에서 병렬 구현하고 P3~P5는 선행 결과를 검증·통합한 뒤 진행한다. PR 생성/게시/병합 승인은 별도다.

## Plan Decomposition
[전체 계획](plan.md)을 P1 게임 객체·규칙, P2 창·출력, P3 월드 렌더링, P4 Canvas UI, P5 통합으로 나눈다. 이 명세의 FR-001~010은 전체 요구사항을 보존하고 plan.md에서 각 계획에 대응한다. 각 계획은 독립 완료 단위를 가진다. 2026-11-10 전체 구현 지시를 받았고 P1은 구현·자동 검증했다. 분할로 요구사항을 삭제하지 않으며 전체 완료는 P5에서 판정한다.

## Intent & Scope
레벨의 객체·배치, 렌더링 씬, 레벨별 규칙 객체를 분리한다. 레벨이 객체를 소유하고 씬이 참조하며 모드는 규칙을 수행하도록 제안한다. 기존 엔진에 입력·업데이트·렌더링 단계를 연결한다. 에셋 없는 도형 검사로 배치·규칙·진행·이미지별 앞뒤 순서·화면 UI·레벨 전환을 확인할 예정이다.
구체 승패·전투·물리·충돌·카메라 추적/줌·컴포넌트 체계·아트 통합·파일 저장/불러오기·레벨 에디터는 제외 제안이다.

## User Scenarios & Testing (mandatory)
### User Story 1 - 레벨 배치와 객체 수명 (Priority: P1)
**Why this priority**: 객체 소유의 단일 기준이 필요하다.
**Independent Test**: 레벨을 열고 배치·생성·제거·닫기와 소유 관계를 검사한다.
**Acceptance Scenarios**:
1. **Given** 배치가 정의된 레벨, **When** 열기, **Then** 배치 상태의 객체가 해당 레벨에 한 번 소속된다.
2. **Given** 레벨 소속 객체, **When** 제거 또는 레벨 닫기, **Then** 정리를 한 번 시도하고 소유 관계를 해제한다.
3. **Given** 이미 생성된 객체나 닫힌 레벨, **When** 잘못된 생성, **Then** 오류로 거부하고 기존 소유를 보존한다.

### User Story 2 - 레벨별 규칙과 단계별 진행 (Priority: P1)
**Why this priority**: 객체 관리와 현재 게임의 규칙을 분리한다.
**Independent Test**: 두 레벨의 서로 다른 규칙 객체와 단계 로그·위치 변화를 확인한다.
**Acceptance Scenarios**:
1. **Given** 활성 레벨과 그 게임모드, **When** 입력·업데이트, **Then** 해당 레벨의 규칙과 객체 상태에만 영향을 준다.
2. **Given** 여러 객체, **When** 한 프레임 진행, **Then** 업데이트에서 시간에 따른 이동을 한 번 적용한 뒤 렌더링한다.
3. **Given** 입력 이벤트 하나 또는 update 전달 중, **When** 생성·제거, **Then** 신규 객체는 같은 전달에 참여하지 않고 제거 객체는 이후 호출에서 제외된다. update 생성 객체는 해당 프레임 렌더에는 보일 수 있다.

### User Story 3 - 렌더링과 레벨 교체 (Priority: P2)
**Why this priority**: 시각 표현이 객체 소유·규칙을 침범하지 않게 한다.
**Independent Test**: 업데이트 후 도형 위치를 그리는지, 레벨 교체 후 참조가 남지 않는지 확인한다.
**Acceptance Scenarios**:
1. **Given** 업데이트를 마친 레벨, **When** 렌더링, **Then** 씬은 현재 객체 상태를 참조하여 그리고 상태를 진행시키지 않는다.
2. **Given** 실행 중인 레벨, **When** 교체 또는 콜백 오류, **Then** 기존 모드·객체·렌더 참조를 정리하고 오류를 숨기지 않는다.
3. **Given** 도형 검사 화면, **When** 생성·제거·레벨 왕복, **Then** 화면과 레벨 객체 상태가 일치한다.
4. **Given** 서로 겹치는 이미지와 UI, **When** 렌더링, **Then** 월드 이미지의 개별 뎁스 순서 뒤에 UI를 UI 내부 순서로 그린다.
5. **Given** 같은 뎁스 또는 업데이트 중 뎁스가 바뀐 항목, **When** 렌더링, **Then** 월드/형제 범위의 동률 등록순을 유지하고 변경은 해당 프레임에 반영하며 업데이트 순서는 바꾸지 않는다.
6. **Given** 겹치는 두 UI 패널, **When** 뒤 패널 자식의 뎁스를 크게 변경, **Then** 그 자식은 앞 패널 전체보다 먼저 그려진다. 부모 숨김은 하위 트리 렌더를 생략하고 부모 제거는 하위 트리 전체를 소유 해제한다.

7. **Given** 화면 밖 객체와 화면 경계에 일부 걸친 이미지, **When** 업데이트 후 렌더링, **Then** 완전히 밖인 항목만 그리지 않고 모든 객체의 업데이트/소유는 유지한다. 보기 영역 이동 시 객체 월드 좌표와 UI 화면 좌표는 변하지 않는다.
8. **Given** 겹친 불투명/반투명 이미지와 반투명 UI, **When** 렌더링, **Then** 기존 뎁스 순서대로 뒤에서 앞으로 합성하고 뒤쪽 그림이 비친다. 공유 이미지의 불투명도는 다음 항목에 누출되지 않는다.

9. **Given** 서로 다른 창 크기/화면비/DPI와 전체화면, **When** 표시 크기를 변경하거나 복귀, **Then** 월드 저장 좌표는 같고 UI 기준점/비율을 유지하며 마우스 위치와 표시가 일치한다. 최소화 중 오류 없이 종료 이벤트를 처리한다.

### Edge Cases
중복 소유·자가 제거·순회 중 생성/제거·부분 초기화 실패·정리 실패·닫는 중 생성·레벨 재진입·다른 레벨에 규칙 객체 공유·제거된 렌더 참조·업데이트/렌더링의 중복 시간 진행·같은 뎁스·이미지 단위 교차 정렬·렌더 실패 후 참조 잔존을 검사한다.

## Requirements (mandatory)
### Functional Requirements
- **FR-001**: 레벨은 객체와 배치 상태를 소유하고 레벨마다 독립적인 게임모드를 가진다. 렌더링 씬과 엔진 연결 역할을 구분한다.
- **FR-002**: 객체의 단일 레벨 소유·생성·제거 수명을 보장한다. 잘못된 생성은 거부하고 반복 제거는 무해하다.
- **FR-003**: 입력 → 업데이트 → 렌더링 순서를 보장한다. 모드 규칙과 객체 동작을 구분하고 순회 중 변경을 안전하게 반영한다.
- **FR-004**: 레벨 교체·초기화 실패 시 모드·객체·렌더 참조를 정리하고 오류를 보존한다.
- **FR-005**: 렌더링 씬은 레벨 객체의 업데이트 후 상태를 참조해 그린다. 도형 검사 화면으로 배치·생성/제거·단계 진행·규칙 분리·레벨 왕복을 확인한다.
- **FR-006**: 자동 검사·실제 창 관찰·사용자 직접 확인을 구분해 기록한다.
- **FR-007**: 객체 내부의 여러 이미지까지 독립적으로 그리기 순서를 지정할 수 있다. 월드와 화면 UI를 구분하고 각 내부 순서를 지키며 UI를 월드 뒤에 그린다. 동률 안정성·현재 프레임 변경 반영·업데이트 순서 보존을 보장한다. 화면 UI는 Canvas 계층으로 소유하고 형제끼리 순서를 비교하며 부모 그림 다음에 하위 트리를 연속해서 그린다는 안을 제안한다. 부모 제거/숨김은 하위 트리에 적용한다.
- **FR-008**: 화면보다 큰 월드를 표현하도록 최소 보기 영역·월드→화면 이동을 제공한다. 이미지 범위가 화면과 완전히 분리된 경우만 렌더에서 제외하며 화면 밖 객체의 소유·업데이트는 유지한다. UI 부모 자기 그림의 제외로 자식 렌더 검사를 생략하지 않는다.
- **FR-009**: 이미지 픽셀 알파와 항목 불투명도를 표준 알파 합성에 반영한다. 반투명 때문에 기존 뎁스 순서를 변경하거나 뒤쪽 항목을 가림 제외하지 않는다. 공유 이미지/도형의 그리기 상태는 성공·실패 뒤 복원한다.
- **FR-010**: 월드·Canvas 논리 좌표·출력 픽셀·창 입력 좌표를 분리한다. 창 크기/화면비/전체화면/DPI 변화에도 위치와 크기를 일관되게 변환하고 입력 역변환·화면 밖 판정에 같은 출력 상태를 사용한다. 크기 0에서는 나눗셈/그리기를 생략한다. 저장된 월드/UI 좌표는 해상도 변경 때문에 재작성하지 않는다.
### Constraints
Python + Pico2D와 기존 게임 환경 유지. 신규 의존성·외부 전송·에셋 제작·PR 없음.

## Assumptions & Open Decisions
기술 제안의 기준은 [architecture](../../docs/architecture.md#게임프레임워크-계약-제안-미구현)다. Level의 dict·Canvas의 roots/children 목록 트리·월드 전역 정렬/UI 형제 정렬을 권장하는 구체안이며 최종 승인 전이다. LevelScene이 Level과 Canvas를 각각 소유하는 것으로 제안한다. UIElement의 논리 로컬 위치·루트 anchor·숨김·부모/자식 수명과 순서, Canvas의 균등 배율을 포함한다. UI 입력/포커스·루트 기준점 외 자동 레이아웃·클리핑·노드별 회전/스케일 상속·reparent는 제외한다.

파일 보관·영속 World·공통 UI 수명·구체 게임 규칙·업데이트 결과 판정 시점은 미정이다. GameMode의 GameObject 상속은 필수가 아니며 물리·simulate 단계는 없다. 객체 규모·변경률·메모리/프레임 예산은 미정이고 독립 Python 비교는 실제 게임 성능 보증이 아니다. 독립 월드/Canvas 좌표와 카메라 투영·가변 출력/전체화면·입력 역변환·화면 밖 제외·표준 알파 합성은 이번 검토안에 포함하며 카메라 추적/줌·가림 판정 제외·화면 밖 update 정지는 포함하지 않는다. 2026-11-10 구현 지시 범위 안에서 진행하며 상세 기술 선택을 사용자 게임 정책 확정으로 표시하지 않는다.
