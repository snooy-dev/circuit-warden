# 게임 설계

상태: **게임 플레이 규칙 미정 / 실행 기반·엔진 프레임워크 구현·검증 완료**

엔진 기능은 `feature/engine`에 통합한다. 주인공 원화·아트 채택 상태는 [아트 기준](art-direction.md)을 따르며 프레임워크 완료를 실제 게임 완성으로 해석하지 않는다.

## 확정 제약

- 프로젝트: Circuit Warden. 구현 기술: Python + Pico2D.
- 사용자가 기획·게임 설계·범위를 결정하고 Codex가 문서화·구현 계획·코드를 담당한다.
- 기본 실행 기반(창·게임 루프·입력 전달·장면 전환)을 이번 작업 범위로 선택했다. 상세 명세·계획은 2026-11-08 사용자 승인을 받았다. 게임 플레이 규칙이나 아트 승인과 별개이며, 기술 계약과 구현 상태는 [architecture](architecture.md)를 참조한다.
- PPTX는 제안서에 가깝다. 손그림 2D 스타일은 고정되지 않았다.

## 미정 설계

플레이어 경험 목표, 핵심 반복 구조, 시스템 목록, 조작·승패 규칙, 제작 범위는 이후 사용자와 확인한다. 코드나 에셋 제작을 위해 임의의 값을 확정하지 않는다.

규칙은 [systems](systems/README.md), 아트는 [art-direction](art-direction.md)에 현재 기준과 선택 이유를 남긴다. 과거 변경 경위는 Git 로그·diff로 확인한다.

## 게임프레임워크 개발 범위

2026-11-10 사용자가 P1~P5 구현과 독립 계획 병렬·후속 계획 순차 통합을 지시했다. 이에 실행·객체·출력·월드·Canvas·통합 프레임워크를 구현·검증했다. 이는 게임 규칙이나 아트의 확정과 별개다.

사용자 구조 제안은 레벨의 객체 배치 보관, 렌더링을 담당하는 씬, 레벨별 규칙 객체인 게임모드다. 일반 프레임 파이프라인을 설명한 뒤 현재는 물리 시뮬레이션이 없으므로 시뮬레이션 단계도 없다고 가정하도록 지시했다. 현재 검토 범위는 입력 → 업데이트 → 렌더링이다. 객체 소유를 레벨에 모으고 씬이 그 객체를 참조하는 방식, 단계별 책임과 클래스 연결은 Codex의 기술 제안이다. 대화상의 이해 확인을 상세 설계 최종 승인으로 기록하지 않는다.

구체 승패·전투·플레이 모드 종류·배치 파일 형식은 미정이다. [기술 계약과 구현 상태](architecture.md#게임프레임워크-계약-제안-미구현)를 사용하되 구체 게임 설계는 사용자와 별도로 정한다.

렌더링에서는 사용자 요청에 따라 이미지별 뎁스와 월드/UI 구분을 검토한다. UI를 월드보다 나중에 그리는 별도 패스, 월드 전역 뎁스와 UI 형제 범위 뎁스, Canvas의 최소 부모/자식 계층과 화면별 UI 수명은 기술 제안이다. UI 하위 트리를 연속해서 그려 패널 자식이 다른 패널 위로 빠져나가지 않도록 제안하며 사용자 확정 사항으로 간주하지 않는다. 실제 HUD·메뉴 내용과 공통 UI 지속 여부는 아직 정하지 않았다.

사용자는 화면보다 큰 월드의 화면 밖 객체와 반투명 표현도 고려하도록 요청했다. 화면 밖은 그리기만 제외하고 업데이트/소유는 유지하는 안이며, 자동 휴면/삭제/언로드는 게임 규칙으로 확정하지 않았다. 최소 보기 원점 이동·이미지 범위 검사·뎁스 순 알파 합성은 기술 제안이다.

사용자는 월드 좌표와 스크린 좌표의 분리, UI 좌표계, 고정되지 않는 창/전체화면 크기를 명시했다. 독립 월드 단위와 UI 논리 단위·출력 변환을 제안한다. 넓은 화면비에서 월드 가로 시야를 늘리는 정책과 UI 기준 크기·최소 창 크기는 최종 게임 설계로 확정되지 않았다.

광범위해진 계획은 사용자 요청에 따라 객체·규칙/창·출력/월드 렌더링/Canvas UI/통합의 다섯 검토 단위로 분리했다. 기존 의도와 미결 사항은 유지하고 각 계획 승인을 전체 승인으로 간주하지 않는다. [분리 계획](../specs/008-game-framework/plan.md)을 따른다.
