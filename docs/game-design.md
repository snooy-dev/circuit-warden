# 게임 설계

상태: **주인공 컨셉·무기 용도·idle 비발검·공격 표현 확정 / 실행 기반·프레임워크·캐릭터 표시와 좌우 이동 검사 구현 / 초기 A/D 이동·클릭 공격 구현 진행 / 피해·승패 미정**

엔진·스프라이트 실행·캐릭터 검사 장면은 main에 통합돼 있다. 주인공 원화·아트 채택 상태는 [아트 기준](art-direction.md)을 따른다. 자동 검사·실제 SDL 검증과 사용자 직접 품질 평가는 [진행 상태](progress.md)에서 구분하며, 검사 기본값을 최종 게임 규칙으로 확정하지 않는다.

## 확정 제약

- 프로젝트: Circuit Warden. 구현 기술: Python + Pico2D.
- 사용자가 기획·게임 설계·범위를 결정하고 Codex가 문서화·구현 계획·코드를 담당한다.
- 기본 실행 기반(창·게임 루프·입력 전달·장면 전환)을 이번 작업 범위로 선택했다. 상세 명세·계획은 2026-11-08 사용자 승인을 받았다. 게임 플레이 규칙이나 아트 승인과 별개이며, 기술 계약과 구현 상태는 [architecture](architecture.md)를 참조한다.
- PPTX는 제안서에 가깝다. 손그림 2D 스타일은 고정되지 않았다.

## 주인공: 워든(Warden)

2026-11-09 사용자가 첨부 원화와 함께 설명한 설정을 현재 기준으로 기록한다.

- 워든은 Circuit Warden의 주인공이며, 전기·전자·에너지 볼을 기반으로 디자인한 전기 생명체다.
- 신체는 전기로 이루어져 있으며, 몸에 전기가 흐르는 모습이 보인다.
- 무기는 **에너지 검**이다. 워든은 검을 휘둘러 적을 베거나 공격을 튕겨낼 수 있다.

- **대기(idle) 중에는 검을 뽑지 않는다.** 검을 손에 꺼내 들지 않은 상태를 기본으로 한다. 공격 모션에서는 검이 나타나 공격한다. 검의 보관 위치·칼집 유무와 출현 방식은 정하지 않았다.
- 공격 표현은 상체를 앞으로 숙인 채 전신에 힘을 실어 캐릭터의 어깨 높이를 베는 느낌이다. 수평 베기에 가깝되 칼날이 보이도록 약간 대각선으로 벤다. 사용자는 모션을 먼저 검토하고 검 출현 VFX는 이후에 검토하기로 했다. 공격 아트는 v5 잠정 승인 상태이며 게임 전투 입력·판정·수치를 확정한 것은 아니다.

원화의 역할과 신체의 흰 무늬 표현, 원본 위치는 [워든 원화 기준](art-direction.md#워든-원화-기준)을 따른다. 초기 A/D 이동·왼쪽 클릭 공격과 공격 중 정지/종료 후 유지 키 반영은 2026-11-11 사용자 요청으로 구현한다. 현재 규칙은 [기본 게임플레이](systems/basic-gameplay.md)가 소유한다. 피해·튕겨내기 판정·대상·수치는 미정이다.

## 미정 설계

플레이어 경험 목표, 핵심 반복 구조, 시스템 목록, 조작·승패 규칙, 제작 범위는 이후 사용자와 확인한다. 코드나 에셋 제작을 위해 임의의 값을 확정하지 않는다.

규칙은 [systems](systems/README.md), 아트는 [art-direction](art-direction.md)에 현재 기준과 선택 이유를 남긴다. 과거 변경 경위는 Git 로그·diff로 확인한다.

## 게임프레임워크 개발 범위

2026-11-10 사용자가 P1~P5 구현과 독립 계획 병렬·후속 계획 순차 통합을 지시했다. 이에 실행·객체·출력·월드·Canvas·통합 프레임워크를 구현·검증했다. 이는 게임 규칙이나 아트의 확정과 별개다.

사용자 구조 제안은 레벨의 객체 배치 보관, 렌더링을 담당하는 씬, 레벨별 규칙 객체인 게임모드다. 일반 프레임 파이프라인을 설명한 뒤 현재는 물리 시뮬레이션이 없으므로 시뮬레이션 단계도 없다고 가정하도록 지시했다. 현재 구현 범위는 입력 → 업데이트 → 렌더링이다. 객체 소유를 레벨에 모으고 씬이 그 객체를 참조하는 방식, 단계별 책임과 클래스 연결은 Codex의 기술 제안이다. 대화상의 이해 확인을 상세 설계 최종 승인으로 기록하지 않는다.

플레이 레벨에는 GameplayMode를 사용하고 타이틀 등 다른 규칙의 레벨에는 향후 별도 모드를 지정한다. 이번에는 타이틀 모드를 만들지 않는다. 구체 승패·피해 규칙·배치 파일 형식은 미정이다. [기술 계약과 구현 상태](architecture.md#게임프레임워크-계약-제안-미구현)를 사용하되 구체 게임 설계는 사용자와 별도로 정한다.

렌더링에서는 사용자 요청에 따라 이미지별 뎁스와 월드/UI 구분을 검토한다. UI를 월드보다 나중에 그리는 별도 패스, 월드 전역 뎁스와 UI 형제 범위 뎁스, Canvas의 최소 부모/자식 계층과 화면별 UI 수명은 기술 제안이다. UI 하위 트리를 연속해서 그려 패널 자식이 다른 패널 위로 빠져나가지 않도록 제안하며 사용자 확정 사항으로 간주하지 않는다. 실제 HUD·메뉴 내용과 공통 UI 지속 여부는 아직 정하지 않았다.

사용자는 화면보다 큰 월드의 화면 밖 객체와 반투명 표현도 고려하도록 요청했다. 화면 밖은 그리기만 제외하고 업데이트/소유는 유지하는 안이며, 자동 휴면/삭제/언로드는 게임 규칙으로 확정하지 않았다. 최소 보기 원점 이동·이미지 범위 검사·뎁스 순 알파 합성은 기술 제안이다.

사용자는 월드 좌표와 스크린 좌표의 분리, UI 좌표계, 고정되지 않는 창/전체화면 크기를 명시했다. 독립 월드 단위와 UI 논리 단위·출력 변환을 제안한다. 넓은 화면비에서 월드 가로 시야를 늘리는 정책과 UI 기준 크기·최소 창 크기는 최종 게임 설계로 확정되지 않았다.

광범위해진 계획은 사용자 요청에 따라 객체·규칙/창·출력/월드 렌더링/Canvas UI/통합의 다섯 검토 단위로 분리했다. 기존 의도와 미결 사항은 유지하고 각 계획 승인을 전체 승인으로 간주하지 않는다. [분리 계획](../specs/008-game-framework/plan.md)을 따른다.
