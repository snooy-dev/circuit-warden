# 게임 설계


상태: **전하 순간이동·연결 효과 구현·검증 / 주인공 컨셉·무기 용도·idle 비발검·공격 표현 확정 / 실행 기반·프레임워크·캐릭터 표시와 좌우 이동 검사 구현 / 초기 A/D 이동·Space 점프·클릭 공격 구현·검증 / 기본 적 전투 구현·검증 / 전체 승패 미정**

엔진·스프라이트 실행·캐릭터 검사 장면은 main에 통합돼 있다. 주인공 원화·아트 채택 상태는 [아트 기준](art-direction.md)을 따른다. 자동 검사·실제 SDL 검증과 사용자 직접 품질 평가는 [진행 상태](progress.md)에서 구분하며, 검사 기본값을 최종 게임 규칙으로 확정하지 않는다.

## 확정 제약

- 프로젝트: Circuit Warden. 구현 기술: Python + Pico2D.
- 사용자가 기획·게임 설계·범위를 결정하고 Codex가 문서화·구현 계획·코드를 담당한다.
- 기본 실행 기반(창·게임 루프·입력 전달·장면 전환)을 이번 작업 범위로 선택했다. 상세 명세·계획은 2026-11-08 사용자 승인을 받았다. 게임 플레이 규칙이나 아트 승인과 별개이며, 기술 계약과 구현 상태는 [architecture](architecture.md)를 참조한다.
- PPTX는 제안서에 가깝다. 손그림 2D 스타일은 고정되지 않았다.

## 핵심 경험: 전하를 통한 순간이동 전투

2026-11-15 사용자 결정으로 전하를 통한 순간이동 이동 시스템을 게임의 차별점이자 정체성으로 삼는다. 목표는 순간이동으로 접근·재배치하며 이어가는 빠른 전투다. 대표 경험은 **전하로 순간이동 → 적 공격 → 다른 전하로 순간이동**이다.

전하를 사용해 적의 돌진을 피하거나 타격 위치로 들어간다. 공중에서 적을 벤 뒤 다른 전하로 바로 이탈할 수 있다. 전하는 워든의 기술과 환경에서 생성되며 배치는 시점에 따라 달라진다. 이동에 성공하면 도착 전하는 사라진다. [전하 시스템](systems/charge-teleport.md).

레벨에 떠 있는 원형 전하의 거리 기반 활성화와 클릭 이동 규칙은 [전하 순간이동](systems/charge-teleport.md)이 소유한다. 정확한 활성화 거리는 실제 플레이로 확정한다. 사용자 구현 요청으로 거리 활성화·클릭 순간이동·기존 행동 즉시 취소를 연결했다. 플레이 후 낙하가 너무 빨라 다음 전하를 누르기 어렵다는 사용자 의견에 따라 공중 도착 후 약하게 위로 뜨는 관성을 적용했다. 100ms 시험 재생의 연결 전류·목표 기준 활성화·순간이동 중 마지막 입력 예약과 실제 창 검증까지 완료했으며 연결 전류는 피해를 주지 않는다. 기본 적 전투와 함께 실행하며 순간이동이 취소한 공격은 타격하지 않는다.

## 주인공: 워든(Warden)

2026-11-09 사용자가 첨부 원화와 함께 설명한 설정을 현재 기준으로 기록한다.

- 워든은 Circuit Warden의 주인공이며, 전기·전자·에너지 볼을 기반으로 디자인한 전기 생명체다.
- 신체는 전기로 이루어져 있으며, 몸에 전기가 흐르는 모습이 보인다.
- 무기는 **에너지 검**이다. 워든은 검을 휘둘러 적을 베거나 공격을 튕겨낼 수 있다.

- **대기(idle) 중에는 검을 뽑지 않는다.** 검을 손에 꺼내 들지 않은 상태를 기본으로 한다. 공격 모션에서는 검이 나타나 공격한다. 검의 보관 위치·칼집 유무와 출현 방식은 정하지 않았다.
- 지상에서는 앞을 베고 공중에서는 전방 아래를 벤다. 두 공격 모두 스윙 방향을 고정한 채 A/D로 이동할 수 있다. 베기에는 검의 궤적을 따라가는 전기 효과를 사용한다. 검 출현 VFX는 보류한다. [아트 기준](art-direction.md#게임에서-사용하는-캐릭터-자산).

몸체 표현과 원본 위치는 [워든 원화 기준](art-direction.md#워든-원화-기준)을 따른다. 훈련장은 지상·공중 이동 공격, 가변 높이 점프, 수평 추적 카메라를 사용한다. 조작·공중 플랫폼은 [기본 게임플레이](systems/basic-gameplay.md), 금속 먼지 덩어리와 피해·체력은 [기본 적 전투](systems/basic-enemy.md)를 따른다. 튕겨내기와 전체 전투 밸런스는 미정이다.

## 첫 레벨 전원 구역

첫 레벨은 컴퓨터 파워서플라이 내부다. 케이스 왼쪽 상단 케이블의 찢어진 피복 사이로 드러난 구리 심선에서 짧은 방전이 시작된다. 갈라진 번개가 바닥을 때리면 시야가 짧게 흔들리고, 발밑으로 불꽃이 퍼지며 워든이 나타난다. R로 재시작하면 등장 연출을 다시 재생하며, 조작 입력이 들어오면 즉시 워든을 드러낸다.

흡기실을 지나면 중앙 접속부에서 왼쪽 위의 닫힌 출력과 오른쪽 아래의 첫 착지면을 함께 볼 수 있다. 케이블을 따라 내려가 팬 아래 점검 갤러리를 서쪽으로 지나고, 바닥에서 방향을 바꾸어 변압실에 진입한다. 변압실의 버스바를 건너면 문이 열교환실, 콘덴서실, 필터실과 동쪽 배전탑으로 이어진다. 열교환실은 방열판의 높이를 따라 이동하고, 콘덴서실은 틈 아래로 떨어져도 돌아올 수 있다. 파워 맵의 몬스터는 이후 제작할 범위다.

갤러리의 점검 덮개는 아래 점검대에서 W를 누르면 열린다. 덮개를 통해 방금 지나온 갤러리로 다시 올라갈 수 있다. 동쪽 배전탑의 릴레이를 복구하면 하층 버스바의 방전이 멎고, 상층의 셔터와 중앙 귀환교, 출력 셔터가 열린다. 배전탑을 점프와 전하로 오른 뒤 필터, 콘덴서, 방열기 위의 상층 통로 세 곳을 지나 중앙 접속부로 돌아온다. 귀환교에서 첫 하강 지점 위를 건너 출력에 닿는다. R은 전원과 점검 덮개를 함께 초기화한다. 전체 진행 규칙과 보스·회복·저장은 미정이다.

`main.py`는 타이틀 메뉴를 열고, `main.py --training`은 플랫폼 훈련장으로 바로 진입한다. 타이틀의 New Game은 전원 구역을 열고 오프닝 컷신을 재생한다. 원경·소품·발판의 hi-bit 에셋과 충돌 배치는 [맵 데이터](../assets/levels/power-supply/map.json), 검사 결과는 [검증 기록](../specs/021-power-supply-level/verification.md)을 참조한다.

흡기 팬, 중앙 접속부의 케이블, 열교환기의 방열핀, 콘덴서와 필터 코일, 배전탑의 퓨즈로 위치를 구분한다. 접속부 케이블은 첫 하강 때와 복구 후 귀환교에서 다시 보인다. 흡기 팬은 고정 하우징과 메쉬 뒤에서 5초에 한 바퀴 돈다. [전체 방 연결](../art/levels/power-supply/annex/room-flow.png) · [아트 기준](art-direction.md#첫-레벨-정비-구역).

첫 레벨은 2×2픽셀 격자를 사용하며 1280×720 기본 창에서 640×360을 최근접 확대한다. 카메라는 현재 방에서 워든을 추적하고 경계에서 멈춘다. 출입구를 통해 방 경계를 넘으면 새 방을 보여 준다. 출입구는 양방향으로 이용할 수 있다.

## 타이틀 메뉴

- **New Game**은 오프닝 컷신을 재생하고 첫 레벨을 시작한다.
- **Settings**는 창 모드와 전체화면을 전환한다. 창 크기는 1280×720과 1024×720을 순환하고 선택 시 창 모드로 전환한다. 변경은 현재 실행에 적용된다. Back 또는 Escape로 타이틀에 돌아온다.
- **Quit**은 게임을 종료한다.

방향키 또는 Tab으로 항목을 이동하고 Enter·Space 또는 마우스 왼쪽 클릭으로 선택한다. 전원 구역 원경 위에 제목과 메뉴를 배치하고, 현재 선택 항목은 짧은 표시와 글자 명도로 구분한다. 화면에 키 가이드는 표시하지 않는다. [타이틀 메뉴 명세](../specs/022-title-menu/spec.md).

## 오프닝 스토리 컷신

전원 구역 안에서 흡기 팬이 돌기 시작하고, 손상된 전선에서 스파크가 튀는 순간 팬과 조명이 가라앉는다. 카메라가 물러나며 낙뢰가 닿는 바닥을 드러낸다. 거기서 워든이 등장하고 카메라가 플레이 구도에 도착하면 바로 조작할 수 있다. 약 2.85초 동안 자동 재생하며 Escape 또는 Skip으로 같은 레벨의 조작을 즉시 시작할 수 있다. R은 기존 짧은 낙뢰만 재생하고 `--training`은 훈련장으로 바로 들어간다. [연출 구성](../specs/023-story-intro/plan.md#storyboard).

## 미정 설계

전하 순간이동을 통한 빠른 전투 경험은 확정했다. 순간이동 상승 관성의 시험값·전체 전투 밸런스, 전체 진행·보상 반복 구조, 승패 규칙과 전체 제작 범위는 미정이다. 코드나 에셋 제작을 위해 임의의 값을 확정하지 않는다.

규칙은 [systems](systems/README.md), 아트는 [art-direction](art-direction.md)에 현재 기준과 선택 이유를 남긴다. 과거 변경 경위는 Git 로그·diff로 확인한다.

## 게임프레임워크 개발 범위

2026-11-10 사용자가 P1~P5 구현과 독립 계획 병렬·후속 계획 순차 통합을 지시했다. 이에 실행·객체·출력·월드·Canvas·통합 프레임워크를 구현·검증했다. 이는 게임 규칙이나 아트의 확정과 별개다.

사용자 구조 제안은 레벨의 객체 배치 보관, 렌더링을 담당하는 씬, 레벨별 규칙 객체인 게임모드다. 일반 프레임 파이프라인을 설명한 뒤 현재는 물리 시뮬레이션이 없으므로 시뮬레이션 단계도 없다고 가정하도록 지시했다. 현재 구현 범위는 입력 → 업데이트 → 렌더링이다. 객체 소유를 레벨에 모으고 씬이 그 객체를 참조하는 방식, 단계별 책임과 클래스 연결은 Codex의 기술 제안이다. 대화상의 이해 확인을 상세 설계 최종 승인으로 기록하지 않는다.

플레이 레벨에는 GameplayMode를 사용한다. 타이틀과 설정은 독립 장면인 TitleScene에서 처리한다. 전체 게임의 승패 규칙과 배치 파일 형식은 미정이다. [게임프레임워크 계약과 구현 상태](architecture.md#게임프레임워크-계약과-구현-상태).

렌더링에서는 사용자 요청에 따라 이미지별 뎁스와 월드/UI 구분을 검토한다. UI를 월드보다 나중에 그리는 별도 패스, 월드 전역 뎁스와 UI 형제 범위 뎁스, Canvas의 최소 부모/자식 계층과 화면별 UI 수명은 기술 제안이다. UI 하위 트리를 연속해서 그려 패널 자식이 다른 패널 위로 빠져나가지 않도록 제안하며 사용자 확정 사항으로 간주하지 않는다. 게임플레이 HUD 내용과 공통 UI 지속 여부는 아직 정하지 않았다.

사용자는 화면보다 큰 월드의 화면 밖 객체와 반투명 표현도 고려하도록 요청했다. 화면 밖은 그리기만 제외하고 업데이트/소유는 유지하는 안이며, 자동 휴면/삭제/언로드는 게임 규칙으로 확정하지 않았다. 최소 보기 원점 이동·이미지 범위 검사·뎁스 순 알파 합성은 기술 제안이다.

사용자는 월드 좌표와 스크린 좌표의 분리, UI 좌표계, 고정되지 않는 창/전체화면 크기를 명시했다. 독립 월드 단위와 UI 논리 단위·출력 변환을 제안한다. 넓은 화면비에서 월드 가로 시야를 늘리는 정책과 UI 기준 크기·최소 창 크기는 최종 게임 설계로 확정되지 않았다.

광범위해진 계획은 사용자 요청에 따라 객체·규칙/창·출력/월드 렌더링/Canvas UI/통합의 다섯 검토 단위로 분리했다. 기존 의도와 미결 사항은 유지하고 각 계획 승인을 전체 승인으로 간주하지 않는다. [분리 계획](../specs/008-game-framework/plan.md)을 따른다.

사용자 요청으로 대시를 구현했다. Run 모션을 재사용하고 거리는 키2배인166 월드 단위이며 지상·공중 사용/공중1회로 정했다. 입력·중력·우선순위의 기술 기본안과 제외 범위는 [기본 조작](systems/basic-gameplay.md#대시)을 따른다.

사용자 요청으로 승인된 전용 대시와 전류 잔광을 연결했다. 준비100ms·이동200ms·복귀167ms 전체의 행동 잠금은 후속 답변으로 정했다. 거리166 월드 단위와 공중1회 규칙을 유지하며 상세 규칙은 [기본 조작](systems/basic-gameplay.md#대시)을 따른다.

대시 중 바로 떨어지지 않도록 체공을 늘려 달라는 사용자 요청을 반영했다. 기술 기본안은 이동200ms의 수직 운동 일시 정지이며 수평 거리·행동 잠금 시간은 유지한다.

사용자 요청으로 전용 점프 v13 hibit v2를 게임에 적용했다. 시작200ms 후 이륙·착지300ms 잠금은 후속 답변이며 기존 높이166 월드 단위·상승400ms·공중 조작은 유지한다. 상세 단계/대시 결합 규칙은 [기본 조작](systems/basic-gameplay.md#점프)을 따른다.

사용자 요청으로 우클릭에 가장 가까운 활성 전하 자동 선택을 추가했다. 세부 선택·예약 규칙은 [전하 시스템](systems/charge-teleport.md#우클릭-자동-선택)을 따른다.
