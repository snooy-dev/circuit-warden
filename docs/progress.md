# 진행 상태

반복 스프라이트 작업은 문서화 워크플로우 없이 진행한다. 현재 검토 대상은 [아트 기준](art-direction.md#현재-제작-상태)을 참조한다.

갱신일: 2026-11-11

## 현재 단계

- **엔진/게임 API 책임 경계 정리 완료**: 사용자 승인 범위로 game_framework 공개 조작 API와 engine 내부 실행을 분리하고 demos·tests/unit·integration·smoke를 분류했다. 기존 공개 import·실행 명령을 유지하며 현재 구조는 [기술 구조](architecture.md#코드-폴더-구조)를 따른다.
- **각 소스 브랜치 기준 동기화 승인**: 2026-11-11 사용자가 충돌 방지를 위해 feature/engine을 각 소스 브랜치로 가져오는 것을 명시 승인했다. a32333c 기준의 최신 정책·아트·제작 스크립트를 보존하고 동일한 공통 구조 결과를 사용한다. 대상 feature/engine으로의 병합이나 PR은 수행하지 않는다.
- 전체 자동 90개·독점 SDL 통합 16단계 통과 근거를 보존했다. 기준 동기화는 런타임·검사·의존성이 e3a0029와 같아 검사를 반복하지 않는다. [최신 검증](../specs/008-game-framework/verification.md)을 따른다.

- **엔진 통합 브랜치: `feature/engine`.** 2026-11-10 사용자가 게임 구현 전의 엔진 기능을 이 브랜치에 모으도록 지시했다. 최신 main의 아트·정책과 feature/world-rendering의 P1~P5 완료 결과를 통합했다. 기존 준비 브랜치는 중복 병합하지 않는다.
- **008 프레임워크 구현·검증 완료.** 객체/레벨 수명·가변 출력·월드 렌더링·Canvas·통합 검사 화면까지이며 실제 게임은 아직 없다. [계획](../specs/008-game-framework/plan.md), [검증 결과](../specs/008-game-framework/verification.md)를 따른다. 감사 기준 bda35a8에서 자동 85개와 실제 SDL 통합 16단계가 통과했다.

- **기본 실행 기반 구현·검증 완료.**
- 승인 근거: 사용자가 명세·계획 시각화를 검토한 뒤 “이 계획을 승인한다”고 확인했다.
- 완료 범위: 창·게임 루프·입력 전달·장면 전환과 도형 기반 검사 화면.
- 완료 기능: [001-engine-foundation](../specs/001-engine-foundation/spec.md). [검증 결과](../specs/001-engine-foundation/verification.md) 참조.
- 아트: idle·걷기·Run 잠정 승인, 이전 달리기 보류, 공격 검토 대기. 2026-11-10 사용자 결정으로 명암·비율 복원과 골반 연동·꼬리/다리 경계를 수정한 Run v4를 잠정 승인으로 올리고 기존 Run v3는 이전 후보로 강등했다. 양쪽 프레임은 보존한다. 현재 결과와 기준은 [아트 기준](art-direction.md#현재-제작-상태)을 따른다. 게임에 통합한 자산은 없다.
- 자동 검사 16개 통과. 실제 화면·시간 이동·마우스·창 닫기는 Codex가 확인했고, Space 왕복·Escape 종료는 사용자가 직접 정상 확인했다.
- **워든 컨셉·기준 원화 기록 완료 / idle·걷기·Run 잠정 승인.** 2026-11-09 사용자가 첨부한 두 이미지를 워든의 원화로 지정하고 설정 기록을 요청했다. [게임 설계](game-design.md#주인공-워든warden)와 [아트 기준](art-direction.md#워든-원화-기준)에 반영했다. idle·걷기·Run은 art 내 잠정 승인이고 이전 달리기는 보류다. 게임에 통합한 자산은 없다. 이전 생성물은 보존 자료이며 이번에 명시된 원화·설정 외의 승인·규격·미완료 작업을 승계하지 않는다.

## 확정 사항

- Python + Pico2D. 게임 기능 개발은 Spec Kit 흐름을 사용하고, 반복 스프라이트 생성·보정은 문서화 흐름에서 제외한다.
- 개발 요청 범위 안에서 명세·계획을 제시하고 별도 승인 대기 없이 구현한다. 최소 실행 가능한 틀부터 확장하며 검증·문서 갱신·커밋을 증분마다 반복한다. PR 생성·게시·병합은 승인 대상으로 둔다.
- 독립적인 기능 개발에만 `feature/<기능명>` 브랜치를 사용한다. 단순 문서·지침 갱신과 소규모 아트 보정은 현재 브랜치에서 처리하며 동시 작업에는 워크트리를 권장한다. 서브에이전트는 난도·지시 구체성에 따라 모델과 추론 수준을 선택한다. 상세 기준은 [워크플로우](workflow.md)를 따른다.
- 게임 .venv와 도구 .local-tools/python 환경 분리. 로컬 스킬·도구는 .git/info/exclude로 제외한다.
- 기술 계약과 검증 기본값은 [architecture](architecture.md)가 소유한다.
- 리소스 보관은 `art/`(로컬 제작·보관)와 `assets/`(실제 게임용)로 구분한다. 이번 초기화는 기존 파일을 삭제하거나 게임에 통합하지 않는다. [리소스 보관 구분](art-direction.md#리소스-보관-구분) 참조.

## 미결 사항

- 기본 실행 기반과 008 엔진 프레임워크의 필수 미완료 기능은 없다. 물리 키 조작·실물 고DPI/모니터 이동·성능 한계는 008에서 미확인이다.
- 워든의 컨셉·에너지 검의 용도·idle 비발검 외의 게임 의도·세부 규칙·제작 범위, 게임 전체 아트 스타일·규격은 미정이다.
- 자동 UI 도구의 키 입력은 반응을 확인하지 못했다. 실제 사용자 키 조작은 정상이며 도구 자체의 원인은 조사하지 않았다.

## 지침 정비 기준

2026-11-10 사용자 요청으로 반복 스프라이트의 Spec Kit 문서화를 중단하고 기존 관련 작업 문서를 제거한다. 결과·검사는 채팅으로 보고하고 채택 상태·장기 기준만 기존 docs에 유지한다. 제작 스크립트·검사 데이터와 아트는 보존한다. 후속 누락 정리 요청에 따라 도구 문서의 이전 아트 상태·기능 문서 요구와 AGENTS의 아트 명세·계획 요구를 정리하고 대체된 지침 검증 문서를 제거했다.

2026-11-10 사용자가 기능별 feature 브랜치, 동시 작업의 워크트리 권장, 작은 단위의 지속 개발·커밋, PR 외 승인 절차 제거, OpenAI 권장에 따른 서브에이전트 모델/추론 수준 선택을 요청했다. 이 지시가 이전의 별도 구현 승인·요청 시에만 커밋 규칙을 대체한다. 최신 사용자 지시에 따라 `warden-shading-restore`, `warden-color-audit`, `incremental-workflow` 규모의 작업에는 새 브랜치를 만들지 않는다. AGENTS·constitution 2.2.0·workflow·프로젝트 템플릿과 overlay에 반영했다. 이번 수정은 현재 브랜치에서 처리하며 기존 미커밋 작업을 보존한다. 최신 검증과 한계는 [개발 방식 검증](workflow-verification.md)을 참조한다.

지침 정비 자체는 새 생성·에셋 변경·게임 통합·Drive 업로드의 승인이 아니다. 이후 아트 제작 권한은 위 기능별 사용자 지시를 따른다. 정책 검증 결과는 [개발 방식 검증](workflow-verification.md)을 참조한다. 기본 실행 기반의 승인·완료 상태는 유지한다.

## 원화 설정 기록

워든의 컨셉·신체 표현·에너지 검과 첨부 원화, 사용자가 복사한 로컬 원화의 확인·참조 위치를 기록했다. `art/warden/reference/`의 두 파일을 열어 확인했고, [아트 기준](art-direction.md#워든-원화-기준)의 참조를 실제 파일명에 맞게 갱신했다. 원화 기록 자체는 새 아트 생성이나 게임 구현·통합의 승인이 아니며 이후 권한은 기능별 지시를 따른다. 원화와 현재 설정은 아트 기준에 유지한다.

## 다음 작업

엔진 개발의 통합 대상은 `feature/engine`이다. 승인된 구조 정리는 소스 브랜치에서 공통 결과로 준비하며 PR·대상 병합 전 상태다. 이번 통합은 원본 main 작업 폴더의 미커밋 변경 7개를 가져오거나 수정하지 않는다. 실행 테스트 삭제는 제안 단계이며, 동일 코드·환경에서 이미 통과한 검사를 문서/브랜치 정리만으로 반복하지 않는다. 검사 선택 기준은 [워크플로우](workflow.md#검사-실행-범위)를 따른다.

사용자가 공격의 앞으로 숙인 전신 동작·어깨 높이 베기·앞발 디딤·검 원근·짧은 팔과 손잡이 연결·회수 동작을 검토한다. 검 출현 VFX는 이후 별도로 정한다. idle·걷기·Run은 잠정 승인, 이전 달리기는 보류 상태를 유지한다. 게임 통합은 별도 승인 전까지 하지 않는다.
