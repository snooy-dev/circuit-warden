# 진행 상태

갱신일: 2026-11-11

## 현재 단계

- **테스트 정리·검사 정책 경량화:** 사용자 요청으로 초기 데모·일회성 구조·검사 장면 자체의 자동 검사 15개를 제거했다. 작은 기능은 직접 동작 확인을 기본으로 하며 전체 회귀는 필요한 통합 변경에만 선택한다. [검사 실행 범위](workflow.md#검사-실행-범위)를 따른다.

- 엔진 패키지·스프라이트 통합은 자동 106개와 실제 PNG·SDL 8단계 검사를 통과했고 [Draft PR #2](https://github.com/snooy-dev/circuit-warden/pull/2)를 생성했다. main은 병합하지 않았다.
- 사용자 요청·중단 후 계속 지시에 따라 `feature/character-movement`에서 캐릭터 표시·좌우 이동을 구현했다. 자동 116개 및 실제 PNG·SDL 입력/화면 검사를 통과했다. 사용자 직접 조작·품질 평가는 미확인이다. [010 명세](../specs/010-character-movement/spec.md)·[계획](../specs/010-character-movement/plan.md)·[검증](../specs/010-character-movement/verification.md)을 따른다.
- idle v7·Run v4 좌우 시트를 버전 없는 assets/warden 이름으로 복사했고 3개 SHA-256·규격·시간이 원본과 일치했다. `.gitattributes`에 PNG binary를 명시했다. 원본 art를 수정하지 않았다.

## 확정 범위와 가정

- Python + Pico2D, 기존 engine/game_framework API를 재사용한다. 표시·키 유지 이동·정지·idle/Run 전환·방향·경계·포커스 정리를 검사한다.
- 이동 축·키·속도·배율·바닥선은 [기술 구조](architecture.md#캐릭터-이동-검사)의 검사 기본값이며 최종 게임 규칙이 아니다. 전투·VFX·충돌·물리·추가 아트 생성은 포함하지 않는다.
- 원본 main 작업 폴더의 미커밋 정책·도구 변경을 보존하고 별도 파일 사본에서 검증하며 원격 예상 head를 확인해 게시한다.

## 미결 사항

- 010 사용자 직접 조작과 최종 이동감·미술 품질 평가. 코드·자동/실제 창 검증 근거는 게임 브랜치에 보존한다.
- 009의 이전 사용자 직접 확인·확인 후 임시 자료 정리(T013/T014/T016). 해당 자료는 보존한다.
- 엔진 PR 병합, 게임 PR 생성·병합은 별도 결정이다.
- 최종 이동감·시각적 품질의 사용자 직접 확인, 실물 고DPI·대량 객체 성능·리셋 자동 복구는 미확인이다.

## 게임 개발 준비

- 기본 실행은 main.py, 플레이어 상태·입력·재생은 game/character.py, 레벨 배치·장면 수명은 game/scene.py다. engine/game_framework에 게임 규칙을 넣지 않는다.
- 초기 사각형 데모·일회성/검사 장면 전용 테스트·중복 출력 검사를 정리했고, 필요한 월드/UI 검사 장면은 tests/fixtures로 분리했다. [검사 선택](../tests/README.md)을 사용한다.
- 새 의존성·범용 관리자·전투 뼈대를 먼저 추가하지 않는다. 현재 캐릭터 실행 기반을 다음 기능의 출발점으로 사용한다.

## 다음 작업

사용자가 다음 플레이 기능의 범위를 정하면 해당 시스템 명세부터 작은 플레이 가능한 증분으로 구현한다. 현재 기준 문서에서 미정인 항목은 아래와 같다.

| 다음 설계 결정 | 정할 내용 | 구현 연결 지점 |
|---|---|---|
| 이동 규칙 | 최종 이동 축·속도·경계, 점프/물리 필요 여부 | game/character.py |
| 첫 상호작용 | 플레이어 행동·입력·대상·결과 | 게임 시스템 규칙 확정 후 game에 추가 |
| 첫 플레이 목표 | 무엇을 달성/실패하면 검사를 끝낼지 | game/scene.py·GameMode |

현재 기술 기본값을 위 규칙의 사용자 승인으로 취급하지 않는다. 엔진 Draft PR #2 병합과 게임 PR 생성은 별도 결정이다. 009 임시 자료는 사용자 확인 전 보존한다.
