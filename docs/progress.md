# 진행 상태

갱신일: 2026-11-11

## 현재 단계

- **main 동기화·문서 정합성 정리:** 사용자 요청으로 로컬 변경을 백업하고 원격의 30개 커밋을 fast-forward했다. 기준은 PR #3 병합 커밋 `1e3b6ad`다. 충돌 문서는 현재 구현과 기존 사용자 정책·아트 결정을 함께 반영한다. 검증 근거는 [개발 방식 검증](workflow-verification.md#문서-정합성-검토와-커밋)을 따른다.
- **엔진·스프라이트·캐릭터 검사 구현:** main에 엔진 패키지·P1~P5 프레임워크·스프라이트 실행과 워든 표시·좌우 이동이 포함돼 있다. 스프라이트 조사·제안 단계의 구현 보류와 main 미통합 상태는 이후 구현·병합으로 대체됐다. [008 검증](../specs/008-game-framework/verification.md)·[009 검증](../specs/009-sprite-runtime/verification.md)·[010 명세](../specs/010-character-movement/spec.md)·[계획](../specs/010-character-movement/plan.md)·[검증](../specs/010-character-movement/verification.md)을 따른다.
- **검증 상태:** 캐릭터 구현 당시 자동 116개와 실제 PNG·SDL 입력/화면 검사를 통과했다. 이후 불필요한 검사 15개를 정리해 현재 탐색 수는 101개다. 정리 단계에서 실행한 렌더 검사 1개와 재사용한 이전 결과를 구분하며, 101개 전체를 새로 실행한 것으로 표시하지 않는다. 사용자 직접 조작·품질 평가는 미확인이다.
- **아트:** idle·걷기·Run·공격 잠정 승인, 이전 달리기 보류. idle v7·Run v4 좌우 시트 3개는 `assets/warden/`에 복사해 캐릭터 검사에 연결했다. 원본 SHA-256·규격·시간을 보존하며 걷기·공격·VFX는 게임에 연결하지 않았다. 원본·이전 후보와 공격 v5의 알려진 검사 한계는 [아트 기준](art-direction.md#현재-제작-상태)을 따른다.

## 확정 범위와 가정

- 사용자 요청으로 기존 기능 브랜치 재사용 시 최신 `origin/main`을 반영하는 [동기화 절차](workflow.md#기존-브랜치-동기화)를 기록했다. 이번 작업은 지침 문서화이며 실제 fetch·merge·rebase는 수행하지 않는다.
- Python + Pico2D, 기존 engine/game_framework API를 재사용한다. 표시·키 유지 이동·정지·idle/Run 전환·방향·경계·포커스 정리를 검사한다.
- 이동 축·키·속도·배율·바닥선은 [기술 구조](architecture.md#캐릭터-이동-검사)의 검사 기본값이며 최종 게임 규칙이 아니다. 전투·VFX·충돌·물리·추가 아트 생성은 포함하지 않는다.
- 반복 스프라이트 제작·보정은 Spec Kit 문서화에서 제외한다. 작은 기능은 직접 동작 확인을 기본으로 하고 자동·전체 검사는 [검사 실행 범위](workflow.md#검사-실행-범위)에 따라 선택한다.
- 커밋은 영어 type/scope와 한국어 요약·본문을 사용한다. 기존 이력 재작성은 수행하지 않는다. 로컬 문서 선택 규칙·FFmpeg 도구 설정을 보존하며 게임 `.venv`와 도구 `.local-tools/python`을 분리한다.
- 이번 동기화는 기존 변경의 통합·정합성 수정 범위다. 새 기능·아트 생성·원격 게시의 승인으로 확대하지 않는다. 미추적 `.codex/`는 로컬에 보존한다.

## 미결 사항

- 010 사용자 직접 조작과 최종 이동감·미술 품질 평가.
- 009의 이전 사용자 직접 확인·확인 후 임시 자료 정리(T013/T014/T016). 해당 자료는 보존한다.
- 실물 고DPI·대량 객체 성능·리셋 자동 복구는 미확인이다.
- 최종 이동·전투·승패 규칙과 게임 전체 아트 스타일·규격은 미정이다.

## 게임 개발 준비

- 기본 실행은 main.py, 플레이어 상태·입력·재생은 game/character.py, 레벨 배치·장면 수명은 game/scene.py다. engine/game_framework에 게임 규칙을 넣지 않는다.
- 초기 사각형 데모·일회성/검사 장면 전용 테스트·중복 출력 검사는 정리했고, 필요한 월드/UI 검사 장면은 tests/fixtures로 분리했다. [검사 선택](../tests/README.md)을 사용한다.
- 새 의존성·범용 관리자·전투 뼈대를 먼저 추가하지 않는다. 현재 캐릭터 실행 기반을 다음 기능의 출발점으로 사용한다.

## 다음 작업

사용자가 다음 플레이 기능의 범위를 정하면 해당 시스템 명세부터 작은 플레이 가능한 증분으로 구현한다. 현재 기준 문서에서 미정인 항목은 아래와 같다.

| 다음 설계 결정 | 정할 내용 | 구현 연결 지점 |
|---|---|---|
| 이동 규칙 | 최종 이동 축·속도·경계, 점프/물리 필요 여부 | game/character.py |
| 첫 상호작용 | 플레이어 행동·입력·대상·결과 | 게임 시스템 규칙 확정 후 game에 추가 |
| 첫 플레이 목표 | 무엇을 달성/실패하면 검사를 끝낼지 | game/scene.py·GameMode |

현재 기술 기본값을 위 규칙의 사용자 승인으로 취급하지 않는다. 009 임시 자료는 사용자 확인 전 보존한다.
