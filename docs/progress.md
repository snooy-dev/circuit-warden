## 확정 사항

- Python + Pico2D, Spec Kit 단일 흐름과 docs 갱신 필수.
- 개발 요청 범위 안에서 명세·계획을 제시하고 별도 승인 대기 없이 구현한다. 최소 실행 가능한 틀부터 확장하며 검증·문서 갱신·커밋을 증분마다 반복한다. PR 생성·게시·병합은 승인 대상으로 둔다.
- 독립적인 기능 개발에만 `feature/<기능명>` 브랜치를 사용한다. 단순 문서·지침 갱신과 소규모 아트 보정은 현재 브랜치에서 처리하며 동시 작업에는 워크트리를 권장한다. 서브에이전트는 난도·지시 구체성에 따라 모델과 추론 수준을 선택한다. 상세 기준은 [워크플로우](workflow.md)를 따른다.
- 게임 .venv와 도구 .local-tools/python 환경 분리. 로컬 스킬·도구는 .git/info/exclude로 제외한다.
- 기술 계약과 검증 기본값은 [architecture](architecture.md)가 소유한다.

## 미결 사항

- 이번 기본 실행 기반의 필수 미완료 작업은 없다.
- 게임 의도·규칙·제작 범위, 아트 스타일·규격은 별도 미정이다.
- 자동 UI 도구의 키 입력은 반응을 확인하지 못했다. 실제 사용자 키 조작은 정상이며 도구 자체의 원인은 조사하지 않았다.

## 개발 방식 조정

2026-11-10 사용자가 기능별 feature 브랜치, 동시 작업의 워크트리 권장, 작은 단위의 지속 개발·커밋, PR 외 승인 절차 제거, OpenAI 권장에 따른 서브에이전트 모델/추론 수준 선택을 요청했다. 이 지시가 이전의 별도 구현 승인·요청 시에만 커밋 규칙을 대체한다. 최신 사용자 지시에 따라 `warden-shading-restore`, `warden-color-audit`, `incremental-workflow` 규모의 작업에는 새 브랜치를 만들지 않는다. AGENTS·constitution 2.1.0·workflow·프로젝트 템플릿과 overlay에 반영했다. 이번 수정은 현재 브랜치에서 처리하며 기존 미커밋 작업을 보존한다. 최신 검증과 한계는 [개발 방식 검증](workflow-verification.md)을 참조한다.
