# 워든 idle·Run 색감 검사

검사일: 2026-11-10. 사용자 요청은 잠정 승인 Run과 idle의 색감 차이 검사다. 보정·재생성·승인 철회·게임 통합은 수행하지 않았다.

## 판정

**색감 불일치를 확인했다.** RGB 팔레트는 같은 16색이지만 밝은 시안색이 차지하는 면적과 명암 배치가 다르다. Run에서만 생긴 변화가 아니라 걷기용으로 생성한 측면 기준 이미지부터 이어지는 차이다. 사용자 지정 원화와 이 파생 이미지를 구분해야 한다. 기존의 팔레트 포함 여부 검사는 동작 간 색감 일치까지 검증하지 못했다.

| 전체 불투명 픽셀·전 프레임 집계 | idle v7 | 걷기 v4 오른쪽 | Run v3 오른쪽 |
|---|---:|---:|---:|
| 분석 프레임 | 48 | 24 | 16 |
| 실제 사용 RGB 색 수 | 16 | 16 | 16 |
| 밝은 시안 계열 면적(G≥171) | 26.59% | 50.95% | 50.98% |
| 어두운 색 면적(G≤62) | 21.99% | 21.88% | 21.71% |
| 평균 선형 상대 휘도 | 0.23687 | 0.31693 | 0.31701 |

Run의 평균 선형 상대 휘도는 idle보다 약 33.8% 높다. 이는 sRGB를 선형화해 0.2126R+0.7152G+0.0722B로 계산한 픽셀 평균이며, 지각상 밝기가 33.8% 증가했다는 뜻은 아니다. 시안 분류는 이 공통 팔레트 안에서 G≥171인 색을 묶은 검사 기준이다. 눈·외곽선·전류를 포함하며 배경과 투명 픽셀은 제외했다. 자세와 시점 차이 때문에 동일 신체 표면의 일대일 색차로 해석하지 않는다.

## 원인과 시각 확인

사용자가 지정한 [기본 원화](../art/warden/reference/master-source.png)와 걷기 제작 때 생성한 [측면 기준 이미지](../art/warden/walk-hibit/master-v1/master_rgba.png)를 직접 열어 비교했다. 앞선 설명에서 후자를 “측면 원화”라고 부른 것은 출처 구분이 불명확한 표현이었다. 사용자는 두 이미지를 본 뒤 차이가 원본 단계에서 나타난다고 확인했다.

기본 원화는 청색 중간 명암이 곡면을 따라 여러 단계로 이어진다. 측면 기준 이미지는 큰 시안 면, 옅은 노란 하이라이트, 보라색 그림자로 재해석됐고 얼굴·귀의 중간 명암이 단순해졌다. 따라서 각도에 따른 색 면적 변화만으로 설명할 문제가 아니라 전체 색조와 입체감의 불일치다. 이것은 두 소스와 결과 비교에 따른 시각 판정이며 면적 통계만으로 입체감을 측정한 것은 아니다. 공통 16색으로 양자화해도 파생 이미지에서 줄어든 명암 배치를 복원할 수 없다.

idle은 reference/master-source.png를 사용하고, 걷기와 Run은 walk-hibit/master-v1/master_rgba.png를 공유한다. build_idle_v7.py와 build_sprint_v3.py의 팔레트 배열은 동일하며 두 경로 모두 부동소수 RGB 거리로 색을 선택한다. Run의 출처 해시는 ca2a657c736d8c58531b61c44e6b78a5f469a1089a5dca92bd9c7d2c7590f855다.

[동일 배경·배율 비교](../art/warden/color-audit-2026-11-10/comparison.png)를 밝고 어두운 배경에서 관찰했다. 측면 걷기/Run의 이마·귀·얼굴에 큰 시안 면이 있고 idle은 중간 청색의 명암 단계가 더 넓다. 걷기와 Run의 시안 면적 차이는 0.03%p에 불과하다. 측면 기준 이미지의 달라진 색조·명암 구조를 그대로 계승한 것이 주요 원인이다. 모니터나 GIF 재생기만의 현상으로 설명할 수 없으며 PNG 자체에서도 차이가 확인된다.

## 검증과 보존

`./.local-tools/python/Scripts/python.exe art/warden/color-audit-2026-11-10/audit.py` 종료 코드 0. idle 48개·걷기 좌우 48개·Run 좌우 32개, 총 128개 PNG가 각 approval.json의 SHA-256과 일치했다. 전 프레임에서 RGB 색 집합이 동일함도 확인했다. 측정값은 [JSON](../specs/007-warden-sprint-hibit/color-audit-metrics.json)에 보존했다.

처음 임시 검사에서 Windows 기본 문자 인코딩으로 approval.json을 읽다 실패했다. UTF-8을 명시한 위 재현 스크립트로 다시 실행해 통과했다. 생성한 비교 이미지는 기존 PNG를 최근접 3배 확대하고 같은 배경에 배치한 검사 자료이며 원본 색·프레임은 수정하지 않았다.

현재 잠정 승인 분류는 그대로다. progress에는 색감 문제와 보정 미실시 상태를 기록한다. 제작 명세·동작·게임 규칙 변경은 없으므로 새 구현 명세는 만들지 않았다. 수정한다면 Run만 별도 재색칠하기보다 측면 몸체의 중간 청색·시안 명암 분포를 idle 기준으로 조정하고 걷기·Run 및 같은 몸체를 쓰는 공격에 함께 검증하는 편이 일관된다. 이것은 후속 제안이며 이번에는 실행하지 않았다.

게임 실행·모니터 색 관리·GIF별 색 변환은 검사하지 않았다. PNG 자체의 차이를 확인하는 데 게임 테스트는 필요하지 않다.

문서 상대 링크 4개가 존재하며 `git diff --check`는 종료 코드 0이다. 기존 파일의 LF→CRLF 안내만 출력됐다.

사용자 후속 복원 요청은 [009](../specs/009-warden-shading-restore/spec.md)에서 진행한다. 초기 명암 복원과 이후 몸/머리 각도 후보를 구분하며 이후 귀·팔을 줄인 정지 검토 후보를 준비했다. 사용자의후속지시로최신자세Run적용·검증을완료했다.
